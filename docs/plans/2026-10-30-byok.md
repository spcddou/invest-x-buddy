# BYOK implementation plan

Goal: evaluators supply their own OpenAI key without consuming the owner's Gateway quota.
Architecture: masked browser settings separate from workspace; request-only x-openai-key header; AI SDK OpenAI provider on the server. Precedence BYOK > explicitly enabled local Codex CLI > Gateway > explicit rules. A failed BYOK never falls through to owner's Gateway. User authorized this choice, implementation and production deployment; read-only git status/diff only, no secret file reads, no extra approval gate or agents.

1. Write failing tests for precedence, sanitized errors, output guards, rate limiting, browser storage separation and persistence/trace payloads.
2. Implement request model context, shared per-IP fixed-window limiter (process-local, documented), browser storage helpers, masked settings and mode state.
3. Wire context into plan/tool selection, evidence memo and followup; preserve schemas, permissions, approvals, evidence and numeric checks. Never return SDK errors/headers/raw responses.
4. Exercise OpenAI-compatible mock through SDK using a local-only loopback endpoint, Playwright settings and complete model workflow. Keep production requests pointed at OpenAI.
5. Owner revision: use logged-in Codex CLI, no purchased API key. Record now against local next start, 60–180s, real providers, approval/memo/memory and explicit simulated source failure. Reject CLI on hosted production while allowing local NODE_ENV=production.
6. Update README, AI_LOG, TESTING, FINAL_STATUS and demo instructions. Run unit/type/build checks, key-pattern scan, deploy authorized project with npx vercel --prod --yes and run production Playwright.
